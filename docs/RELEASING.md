# Releasing

Everything end-user-facing is built by CI and attached to a GitHub Release when
you push a `v*` tag: `.github/workflows/release.yml` (Windows setup + mod zip)
and `.github/workflows/linux.yml` (Linux tarball, triggered by the published
release).

## One-time setup

### 1. Code signing (SignPath Foundation — free for OSS) — *optional*

The direct-download binaries ship **unsigned by default**: Windows SmartScreen
will warn on first run and some AV engines may flag the PyInstaller bundle.
That is expected until signing is enabled. SignPath is free for qualifying OSS
projects but they prefer projects with existing usage/reputation, so it can be
added later without changing anything else.

1. Apply at <https://signpath.org/apply.html>. Requirements: public repo, OSI
   license ([LICENSE](../LICENSE)), a [code signing policy](CODE_SIGNING.md),
   and downloadable releases.
2. Create a project + artifact configuration in SignPath and note the slugs.
3. Add repository secrets:

   | Secret | Value |
   |--------|-------|
   | `SIGNPATH_API_TOKEN` | SignPath API token |
   | `SIGNPATH_ORGANIZATION_ID` | Organization id |
   | `SIGNPATH_PROJECT_SLUG` | Project slug |
   | `SIGNPATH_SIGNING_POLICY_SLUG` | Signing policy slug |
   | `SIGNPATH_ARTIFACT_CONFIGURATION_SLUG` | Artifact configuration slug |

Without these the release still builds, just unsigned (the CI step is skipped).
Meanwhile, publish the **Microsoft Store** build (section 2) to give users a
warning-free install option.

### 2. Microsoft Store (free for individual developers)

Registration is now **free** for individuals via the new onboarding flow —
the legacy $19 fee is waived. You must start at this exact entry point:

1. Register at <https://storedeveloper.microsoft.com> (sign in with a
   Microsoft account; verify identity with a government-issued ID + selfie).
   Starting from Partner Center or Visual Studio directly gives the **legacy
   paid** flow instead.
2. Reserve the app name **HunterPie Analytics**.
3. Put the exact publisher DN from Partner Center into
   `packaging/msix/AppxManifest.xml` (`Identity/@Publisher`) and update
   `Identity/@Name`.
4. Replace the placeholder tiles in `packaging/msix/Assets/` (generated by
   `packaging/msix/make_assets.py`) with real store art.

## Cutting a release

1. Bump the version in:
   - `backend/app/version.py` (`APP_VERSION`)
   - `packaging/version_info.txt`
   - `packaging/msix/AppxManifest.xml`
   - `installer/HunterPieAnalytics.iss` (`#define AppVersion`)

   `APP_VERSION` is what the in-app updater compares against the release tag,
   so all four must match (it is exposed at `/api/health` as `app_version`).
2. Add the user-facing note to `dashboard/lib/changelog.ts`. The app opens a
   one-time "What's new" popup for the running version (Settings → Data also
   re-opens it); the note ships inside the build, so it works offline and with
   the update check off. Keep it to a few plain sentences, and still write real
   notes on the GitHub release (CI's `generate_release_notes` only lists
   commit subjects).
3. Commit, then tag and push:

   ```sh
   git tag v1.0.0
   git push origin v1.0.0
   ```

4. CI builds and attaches to the Release:
   `HunterPieAnalytics-Setup-*.exe`, `HuntDumper-*.zip`,
   `HunterPieAnalytics-Companion-Proton.zip` (the self-contained companion for
   Linux/Proton, added to the release job from the fork artifact) and
   `SHA256SUMS.txt`.
   A second workflow (`.github/workflows/linux.yml`) runs when the release is
   published, builds `HunterPieAnalytics-linux-*.tar.gz` on **ubuntu-22.04**
   (glibc 2.35 is the oldest supported; the frozen Python cannot run on older
   glibc than the build machine), attaches it, and regenerates `SHA256SUMS.txt`
   so it covers every download. If the automatic run is missed, trigger it
   manually:

   ```sh
   gh workflow run linux.yml -f tag=v1.2.4
   ```
5. Since the direct download is unsigned, mention it in the release notes
   (SmartScreen "More info → Run anyway").
6. The MSIX/Store package is not attached to releases; build it locally with
   `packaging/msix/build-msix.ps1` and upload to Partner Center if publishing to
   the Store.

> **Do not ship a companion without `Languages/`.** The fork build depends on
> the `Localization` git submodule; the CI checkout uses `submodules: recursive`
> and stages `Languages/` explicitly. A build without it crashes on startup (no
> window, no tray icon).

## After the release

- Submit any AV false positives to
  <https://www.microsoft.com/en-us/wdsi/filesubmission>.
- Optionally upload the installer to VirusTotal and link the report in the
  release notes (transparency).
- If/when SignPath signing is enabled, verify with `signtool verify /pa /v <file>`.
